# AF008 — plugins are packages registering an AirflowPlugin (error)

Every plugin lives in its own package directory and registers itself:

```
airflow/plugins/
└── ops_toolkit/
    ├── __init__.py      # class OpsToolkitPlugin(AirflowPlugin): ...
    ├── listeners.py
    ├── macros.py
    └── timetables.py
```

Loose `.py` modules dropped directly into `airflow/plugins/` are not allowed,
and a package that never subclasses `AirflowPlugin` is dead code — Airflow
will not load it.

Why: the package groups an extension's operators / macros / listeners /
timetables so each plugin is independently understandable and removable, and
the `AirflowPlugin` subclass in `__init__.py` is its single registration
point.

**Fix**: create `airflow/plugins/<name>/__init__.py` defining
`class <Name>Plugin(AirflowPlugin)` with the components the plugin exposes,
and move the implementation modules into the package. See
`airflow/plugins/ops_toolkit/` for the reference layout.
