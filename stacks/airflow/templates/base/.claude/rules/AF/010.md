# AF010 — env vars documented in .env.example (error / warning)

`.env.example` is the contract for "what this deployment needs to be
configured". Two things must appear in it:

- every `${VAR}` interpolated by `docker-compose.yml` (**error**)
- every `os.getenv("X")` / `os.environ["X"]` lookup in DAGs and plugins
  (**warning**; `AIRFLOW__*` config keys are exempt — compose/IaC wire those)

Why: a new machine (or a new AWS environment) is configured by copying
`.env.example` and filling in the blanks. Any variable consumed but not
documented there is a deployment landmine.

**Fix**: add the variable to `.env.example` with a safe local default, or a
`CHANGE-ME` placeholder plus a comment saying where the value comes from.
Real secret values never go in `.env.example` — locally they live in `.env`
(gitignored), in AWS in the app secret (`dude iac secrets`).
