# AF001 — dag_id ↔ filename parity (error)

Every DAG file under `airflow/dags/` (outside `lib/`) must declare **exactly
one** DAG with an explicit `dag_id` equal to the file name without `.py`.

Why: one DAG per file, named identically, means the id you see in the Airflow
UI is the file you open in the editor — no grepping through factory modules.

✅ `airflow/dags/examples/example_etl.py`

```python
with DAG(dag_id="example_etl", ...):
    ...
```

❌

```python
# in nightly_jobs.py
with DAG(dag_id="load_customers", ...):   # id ≠ filename
    ...
with DAG(dag_id="load_orders", ...):      # second DAG in the same file
    ...
```

**Fix**: rename the file or the `dag_id` so they match, and split extra DAGs
into their own files. Shared helper code (no DAG) belongs in
`airflow/dags/lib/`.
