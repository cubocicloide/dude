# AF007 — no heavy top-level imports in DAG files (warning)

Heavy libraries (pandas, numpy, torch, tensorflow, sklearn, scipy, polars,
pyarrow) must not be imported at the top of a DAG file — import them inside
the task function that uses them.

Why: top-level imports execute on every dag-processor parse cycle. A single
`import pandas` adds hundreds of milliseconds to *every* parse of that file,
multiplying across files and cycles into real scheduler lag.

✅

```python
@task
def transform(rows: list[dict]) -> list[dict]:
    import pandas as pd   # imported once, when the task actually runs
    ...
```

❌

```python
import pandas as pd       # top of dag file — paid on every parse

@task
def transform(...):
    ...
```

**Fix**: move the import into the task callable. Operator imports
(`airflow.providers.*`) stay at the top — they are needed at parse time and
are cheap.
