# AF009 — requirements.txt pins every package (error)

Every requirement in `airflow/requirements.txt` must be pinned with `==`
(or `~=` for a deliberate compatible-release range).

Why: the Airflow image is rebuilt on every deploy. An unpinned requirement
means two builds of the same commit can ship different code — the classic
"it worked yesterday" incident.

✅

```
httpx==0.28.1
apache-airflow-providers-slack==9.0.0
```

❌

```
httpx
apache-airflow-providers-slack>=8
```

**Fix**: pin the exact version you tested. When adding an
`apache-airflow-providers-*` package, prefer the version from the official
constraints file for the project's Airflow version (see the Dockerfile
comment).
