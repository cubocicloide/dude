# PRJ001 — Example project rule

This file is the prose half of the example project check
(`.dude/lint/checks/PRJ/001.ts`). Rename, edit or delete both together.

## What it does

Nothing yet — the shipped check returns no diagnostics. It exists so you have a
working pair to copy: a rule module, and the Markdown that explains it.

## Why the file is here

`dude explain PRJ001` prints **this file**, and `dude cheatsheet` uses its first
heading as the rule's one-line title. A project rule with no Markdown beside it
still runs, but it can only ever be listed as a bare code — which tells whoever
hits the diagnostic (a teammate, or a coding agent) nothing about how to fix it.

The convention is a sibling file, matching the check's path:

```
.dude/lint/checks/PRJ/001.ts   ← the rule
.dude/lint/checks/PRJ/001.md   ← this file
```

`dude lint` ignores non-module files, so the Markdown never runs as a check.

> Stack rules follow the mirror-image convention — their prose lives under
> `.claude/rules/<GROUP>/<NNN>.md`. Both are served by `dude explain <CODE>`.

## How to fix a violation

Describe the fix here, concretely enough that someone can act on it without
opening the check's source. Start the file with `# <CODE> — <title>` so the
title is picked up.
