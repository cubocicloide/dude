# BE012 — Keep the mobile entry point on run()

`lib.rs` must keep this attribute on `run()`:

```rust
#[cfg_attr(mobile, tauri::mobile_entry_point)]
pub fn run() { … }
```

It is what lets the same `run()` serve the iOS/Android builds produced by
`dude android build` / `dude ios build`. On desktop it compiles to nothing, so
there is never a reason to remove it — but removing it breaks mobile builds
in non-obvious ways (the native project links against a missing entry point).

The same logic applies to the crate setup that supports it: don't change
`[lib] crate-type` in `Cargo.toml` (`staticlib`/`cdylib` are the mobile link
formats) and keep `main.rs` thin (BE002) so desktop and mobile share one code
path.
