# FE005 — Page directory structure and route naming

Every page directory (including `pages/` itself) may contain **only**:

| Item | Meaning |
|------|---------|
| `index.tsx` | The page component (route leaf) |
| `styles.module.css`, `types.tsx`, `constants.tsx`, `functions.tsx` | Page-scoped files |
| `$components/` | Page-local components |
| `$hooks/` | Page-local hooks |
| `$assets/` | Page-local static files |
| `$misc/` | Escape hatch — always warned (FE011) |
| any other directory | A **route segment** |

Route segments must be **kebab-case** (`user-settings`) or a **dynamic param** in brackets (`[id]`, `[userId]`); anything else is an error. The names `components`, `hooks`, `assets`, `misc` are reserved (error) — use the `$`-prefixed folder instead. That is exactly why the `$` prefix exists: a privileged folder can never be confused with a piece of the route path.

```
pages/
  index.tsx                     → route "/"
  users/
    index.tsx                   → route "/users"
    $components/
      UserTable/index.tsx       (not a route — structural)
    [id]/
      index.tsx                 → route "/users/:id"
```

A route directory with no `index.tsx` and no nested route is warned (dead directory). Arbitrary files (`helpers.ts`, …) are warned — put shared logic in `functions.tsx` or `frontend/src/utils/`.
