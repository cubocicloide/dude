# FE009 — Utils domain structure

`frontend/src/utils/` is organised in **domains**: one kebab-case directory per topic, each with the same scope files as any other structured directory.

```
utils/
  index.tsx          ← barrel re-exporting the root modules + domains
  constants.tsx      ← app-wide constants
  functions.tsx      ← generic helpers
  formatters/        ← a domain
    index.tsx        ← mandatory public surface of the domain
    types.tsx
    $assets/
  $misc/             ← escape hatch — always warned (FE011)
```

Rules:

- **Domain naming**: kebab-case (`date-helpers`, `formatters`) — error otherwise.
- **Every domain has an `index.tsx`** (its public surface) — error if missing.
- Allowed files in `utils/` and in each domain: `index.tsx`, `styles.module.css`, `types.tsx`, `constants.tsx`, `functions.tsx` (warning otherwise).
- Allowed directories: nested domains, `$assets/`, `$misc/`. No `$components/` or `$hooks/` in utils — anything rendering or stateful is not a util.
- Domains may nest (matrioska): `utils/dates/parsing/index.tsx` is fine.

To add a new util: pick (or create) the domain, implement in the domain's `functions.tsx`, re-export from its `index.tsx`.
