# PY002 — SQL safety (error for interpolation, warning for raw SQL)

Two tiers:

- **Error** — `frappe.db.sql()` whose query is built dynamically (f-string,
  `%` formatting, `.format(...)`, string concatenation). That is a SQL
  injection waiting for user input to reach it.
- **Warning** — any other raw `frappe.db.sql()`. Prefer `frappe.get_all` /
  `frappe.get_list` or `frappe.qb` (the query builder): they respect the
  permission model, escape everything, and survive schema/engine changes.
  Raw SQL is legitimate for what the ORM genuinely cannot express — keep it
  parameterized.

```python
# ❌ error — injectable
frappe.db.sql(f"select name from `tabHD Ticket` where status = '{status}'")

# ✅ raw but parameterized (warning still nudges toward the ORM)
frappe.db.sql(
    "select status, count(*) from `tabHD Ticket` where opening_date < %(cutoff)s group by status",
    {"cutoff": cutoff},
)

# ✅ preferred
frappe.get_all("HD Ticket", filters={"opening_date": ("<", cutoff)},
               fields=["status", "count(name) as total"], group_by="status")
```

**Fix**: rewrite with `frappe.get_all`/`frappe.qb`; where raw SQL must stay,
pass values via the second argument with `%(name)s` placeholders — never
interpolate them into the query string.
