# PY001 — No unjustified `allow_guest=True` (error)

A whitelisted method with `@frappe.whitelist(allow_guest=True)` is callable by
**unauthenticated** visitors — it bypasses login entirely and becomes part of
your public attack surface. The linter flags every occurrence unless a
justification comment `# guest-ok: <reason>` sits on the same line or the
line directly above.

Most methods never need guest access; the common legitimate cases are public
webforms, health probes and truly public read-only data. Even then: validate
inputs defensively and return the minimum.

```python
# ✅ authenticated (the default)
@frappe.whitelist()
def ticket_stats(): ...

# ✅ deliberate, documented public endpoint
# guest-ok: public status page, returns only aggregate counts
@frappe.whitelist(allow_guest=True)
def public_status(): ...

# ❌ unjustified guest exposure
@frappe.whitelist(allow_guest=True)
def delete_ticket(name): ...
```

**Fix**: drop `allow_guest=True` (callers authenticate via session or API
key), or add a `# guest-ok:` comment explaining why the method is safe to
expose — and make sure it actually is.
