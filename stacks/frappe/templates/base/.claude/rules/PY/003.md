# PY003 — Every DocType should ship tests (warning)

Every DocType bundle should include a `test_<doctype_name>.py` next to its
controller. `bench run-tests --app <app>` (wrapped by `dude test`) discovers
tests from exactly that convention.

Controller logic (`validate`, `on_update`, …) is where business rules live,
and it only runs inside a full frappe context — an untested controller is
effectively unexercised until production. `FrappeTestCase` makes this cheap:
each test runs in a transaction that is rolled back, so tests never leak data
into the site.

```python
# ✅ test_ticket_escalation_rule.py
import frappe
from frappe.tests.utils import FrappeTestCase

class TestTicketEscalationRule(FrappeTestCase):
    def test_non_positive_hours_are_rejected(self):
        rule = frappe.get_doc({
            "doctype": "Ticket Escalation Rule",
            "rule_name": "x", "priority": "High", "hours_until_escalation": 0,
        })
        self.assertRaises(frappe.ValidationError, rule.insert)
```

**Fix**: add a `test_<name>.py` covering at least the validation paths of the
controller. Run it with `dude test --app <app>` (or a single module via
`dude test --module <dotted.path>`).
