# DT004 — Field hygiene: snake_case, unique fieldnames (error)

In every DocType JSON, each `fields[]` entry (layout breaks included) must
have a `fieldname` matching `^[a-z][a-z0-9_]*$`, unique within the DocType.

Fieldnames are not labels: they become **database columns**, **API keys**
(`/api/resource/...`), Jinja/JS attribute names and filter keys. A camelCase
or duplicated fieldname works just well enough to spread through client
scripts and integrations before it breaks something that is painful to
rename (renaming a fieldname later means a patch + data migration).

```json
// ✅
{ "fieldname": "hours_until_escalation", "fieldtype": "Int", "label": "Hours Until Escalation" }

// ❌ camelCase / duplicate
{ "fieldname": "hoursUntilEscalation", ... }
```

**Fix**: rename the fieldname to snake_case (before the DocType carries data;
afterwards use `frappe.reload_doc` + a rename patch), and deduplicate
conflicting entries — keep the one with the intended `fieldtype`.
