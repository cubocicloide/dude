# BE010 — No `null=True` on Char/Text fields (warning)

`CharField`/`TextField` with `null=True` creates **two** "empty" states — `NULL` and `""` — so every consumer must check both. Django's convention: text-like fields are never nullable; use `blank=True` with `default=""`.

```python
# ✅
nickname = models.CharField(max_length=50, blank=True, default="")
```

```python
# ❌
nickname = models.CharField(max_length=50, null=True)
```

**Fix**: drop `null=True`, add `blank=True, default=""`, and write a data migration normalising existing `NULL`s if the column already exists. (Exception: `unique=True` text columns that must allow multiple empties genuinely need `null=True` — document it with a comment.)
