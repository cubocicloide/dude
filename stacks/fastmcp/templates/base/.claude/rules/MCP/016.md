# MCP016 — Client-facing errors are `ToolError`

What a component raises is what the client sees, so predictable failures must be
surfaced deliberately. In a component module:

- **`raise` only `ToolError`.** Raising a bare `Exception`, a built-in, or any
  other type is flagged — those are not client-facing and leak internals. The
  pattern is to catch the service's `DomainError` and re-raise as `ToolError`
  with a clear message:
  ```python
  from fastmcp.exceptions import ToolError

  try:
      return service.divide(a, b)
  except DomainError as e:
      raise ToolError(str(e))
  ```
- **No `assert` for control flow.** An `assert` can be stripped under `python -O`
  and is not a real error path — raise `ToolError` for predictable failures
  instead.

To fix: wrap the failing call, catch the domain error, and raise `ToolError`;
remove any `assert` used to validate input or guard a path.
