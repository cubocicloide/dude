# MCP008 — Thin binding layer

A component module is a **binding layer**: it adapts an MCP call to the feature's
`utils/` (typically `utils/service.py`) and returns the result. Business logic,
I/O, and persistence belong in `utils/`, not in the component.

The deterministic slice of this rule (errors):

- **No I/O-library imports** in a component module —
  `httpx`, `requests`, `aiohttp`, `urllib`, `socket`, `sqlalchemy`, `sqlmodel`,
  `sqlite3`, `psycopg2`, `asyncpg`, `pymongo`, `redis`, `boto3`. Their presence
  means logic has leaked into the binding layer; move it into `utils/service.py`.
- **No `open(`** in a component body — file I/O belongs in `utils/`.
- **No class definitions** in a component module — keep logic in `utils/` and
  schemas in `app/schemas/`.

Advisory (warning): a component body over 15 statements is flagged as too fat —
delegate to `utils/service.py`.

To fix: call into the feature's service from the component and keep the body to a
thin translate-call-translate shape.
