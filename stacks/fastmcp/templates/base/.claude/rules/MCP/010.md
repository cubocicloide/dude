# MCP010 — Resource URI ↔ params consistency

A resource is addressed by a URI, and that URI must agree with the function
signature.

- The URI must carry a **scheme** — `scheme://…` (e.g. `note://…`,
  `config://…`). A URI with no `://` is rejected.
- Every `{placeholder}` in the URI must be a **non-`ctx` parameter** of the
  function (a templated resource).
- Every non-`ctx` parameter must be a `{placeholder}` in the URI. A static
  resource (no placeholders) therefore takes **no** non-`ctx` parameters.

```python
@server.resource("note://{note_id}")          # templated
def note(note_id: str) -> str: ...

@server.resource("config://settings")         # static — no params
def settings() -> dict: ...
```

To fix: align the placeholders and parameters one-to-one (`ctx` excluded), and
ensure the URI literal includes a scheme. A `@server.resource` with no URI
literal at all is also flagged.
