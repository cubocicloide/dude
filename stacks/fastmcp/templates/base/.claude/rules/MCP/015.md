# MCP015 — No `print`; surface via Context or logging

`print(` is banned anywhere under `app/` (tests excluded). This is a correctness
rule, not just style: an MCP server speaks JSON-RPC over **stdio**, so writing to
stdout with `print` corrupts the transport and can break the connection.

Use the right channel instead:

| Intent | Use |
|--------|-----|
| Message the client / model | the MCP `Context` — `await ctx.info(...)`, `ctx.report_progress(...)` |
| Diagnostics for operators | the stdlib `logging` module (logs go to stderr) |

```python
import logging
logger = logging.getLogger(__name__)
logger.info("loaded %d notes", count)   # not print(...)
```

To fix: replace each `print(` with a `ctx` call (client-facing) or a logger call
(diagnostics).
